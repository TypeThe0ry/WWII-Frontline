# B6-gwticket：网关签票延迟（M1-028）

**2026-11-20，PI-109：共享 EPYC 7402 工作站，非参考机。** 本机 100、200、500 并发均达到本批 P50 ≤40 ms，且定版配对测试每轮 P95 ≤50 ms。参考机和受信任 HTTPS 预发布服务未测，M1-028 仍为 `partial`。

## 复现与结果

任务提示的约 52 ms 对应 [B5-E1](loadtest-1119/gateway-ticket-b5-e1.json) 原版夹具优化后 **P95 中位数 51.639 ms**，P50 为 31.745 ms。重建 `27d5a1d` release 后用其原版 200 并发夹具重跑七次：P50/P95 中位数 28.430/49.357 ms、4/7 轮 P95 ≤50 ms；P99 未测。短时突发下的尾延迟仍可复现。

定版配对数据：两版本各七轮，轮流先跑基线或优化版。每轮用新进程、新磁盘 SQLite WAL 库、预注册游客与对局，预连接 HTTP socket 后从同一轮起点计至收到并解码响应；500 请求分摊到三场（100/200 请求用一场）。两版本均启用相同分段指标并固定 `TOKIO_WORKER_THREADS=8`，不绑核、无 TLS、不使用 GPU。表中百分位为**各轮分别计算后取中位数**，最后一列是最慢的优化版轮次 P99。

| 并发 | 基线 P50 / P95 / P99（ms） | 优化 P50 / P95 / P99（ms） | 最慢优化轮 P99（ms） |
| ---: | ---: | ---: | ---: |
| 100 | 14.499 / 25.823 / 26.788 | **4.748 / 6.197 / 6.219** | 8.036 |
| 200 | 32.022 / 53.083 / 54.895 | **12.414 / 15.646 / 15.710** | 17.671 |
| 500 | 66.813 / 114.189 / 117.565 | **25.333 / 29.522 / 29.740** | 41.436 |

另用默认 Tokio 线程数跑三轮：100 并发 P50/P99 中位数 5.533/6.812 ms，500 并发 28.780/33.802 ms；500 并发最慢轮 P50/P99 为 32.398/36.008 ms。定版全部 7,400 个请求成功，每轮内零重复票；无网络/TLS 上线结论。逐轮数据、计数和各段值见 [JSON](m1-gateway-ticket-b6.json)。

## 分段与改动

500 并发，各轮 Prometheus `sum/count` 均值取中位数（ms）。分段不是端到端百分位，不能相加重建 P50/P99。

| 阶段 | B5 基线 | B6 优化 |
| --- | ---: | ---: |
| SQLite 排队（沿用 `pool_wait` 指标标签） | 55.57626 | 3.61680 |
| SQLite 事务阶段（B6 为该请求所在批次提交延迟） | 0.06760 | 1.47012 |
| 鉴权与限流 | 0.00864 | 0.00975 |
| HTTP 请求体 JSON、昵称与路径 ID 解析校验 | 0.00191 | 0.00196 |
| Ed25519 签名 | 0.04008 | 0.04848 |
| 票内容编码、Base64 与 HTTP 响应 JSON | 0.00518 | 0.01104 |
| 请求日志调用（默认级别过滤 DEBUG） | 0.00010 | 0.00013 |

Hyper HTTP 报文解析、socket 调度及客户端调度包含在端到端结果中，未独立计时；启用 DEBUG 的日志 I/O 未测。签名密钥已在进程启动时构造，签票不是带 JWT Header 的访客会话 token；没有改签名输入、密钥或日志策略。单连接直接交接／四连接池仅把 500 并发 P50 降到 58.232／51.253 ms（探索轮），未达到 40 ms。

最终使用一条长驻 SQLite 连接和有界签票队列（512 个排队槽）。不等待凑批，最多把 32 个已就绪请求的同昵称路径合到一次事务，按各请求的心跳截止时间、对局状态、协议、容量、签票公钥和保存昵称过滤，再按对局更新游标；每张票的原游标按模 128 分配，提交成功才交回签发。改名、老会话补档和拒绝沿用逐请求路径；队列等待上限仍为 30 s，未取得连接前已取消的请求不消耗游标。WAL、同步级别、60 s TTL、限流、重放防护和线格式均未改。

## 复跑

```sh
export CARGO_BUILD_JOBS=8
cargo build --release --locked -p frontline-gateway
for n in 100 200 500; do
  TOKIO_WORKER_THREADS=8 python3 scripts/gateway-ticket-load.py target/release/frontline-gateway \
    --protocol-version 4 --concurrency "$n" --runs 7 --report-only --metrics
done
cargo test -p frontline-gateway --locked
scripts/local-ci.sh rust determinism
```

基线用 `27d5a1d` 构建；分段对照仅将本批 `auth/ticket.rs`、`metrics.rs`、`routes.rs` 的计时改动应用到该基线，保留 B5 存储。压测默认仍为 200 并发、P95 ≤50 ms；`--report-only` 放开延迟门槛但仍拒绝错误响应、重复票或指标抓取失败。新增回归覆盖多对局资格与回绕、排队取消、不提交失败的改名，130 并发混合路径校验原票签名、过期字段、管理员标志和存储。持续压力以及混合改名/补档的性能未测。
