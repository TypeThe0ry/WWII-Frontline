## 0. 文档约定

### 0.1 知识产权边界（硬约束）

- 对标品类 = 大规模、高致死率、小队/指挥链/补给/重生网络驱动的二战战术射击；参考作品为 Hell Let Loose（下称 HLL）。本文中"参考作品"/"HLL"仅用于说明品类对标。
- 对参考作品只允许**黑盒观测**：公开视频、自录视频、官方开发日志、玩家 wiki 上公开描述的规则。**禁止**反编译、拆包、内存读取、协议解析、素材提取。
- 规则、流程、信息架构（显示什么信息、怎么交互）可以对标；**一切表达层必须原创**：名称、图标、配色、字体、版式、文案、地图关卡布局、能力命名。游戏内对外名称不得出现参考作品的名称或商标。
- 本文所有数值表是**自行整理**的：史实参数取自公开通用资料并取整；游戏性数值是本项目自拟初值，不是对任何作品数值表的复制。需要与参考作品"手感对齐"的量一律标 `【待测 → REFERENCE_MEASUREMENTS §x】`，由黑盒测量填入，在测量完成前使用本文初值。
- 原创命名（全项目统一）：模式 **Frontline / Assault / Skirmish**；重生点 **Garrison / Outpost / Airhead / Observation Post (OP)**；资源 **Manpower / Munitions / Fuel**；指挥官能力 **Supply Drop / Ammo Drop / Bombing Run / Strafing Run / Precision Strike / Recon Flight / Rally / Airhead**；兵种 14 个（Commander、Officer、Rifleman、Assault、Automatic Rifleman、Medic、Support、Machine Gunner、Anti-Tank、Engineer、Tank Commander、Crewman、Spotter、Sniper）。
- 本文另引入的原创术语：**Supplies**（建造补给点，装在 Supply Crate 里，区别于战略资源 Manpower/Munitions/Fuel）、**Strongpoint**（战线据点）、**Sector**（据点所属的地图分区）、**Line**（战线编号 L1–L5）。

### 0.2 标注与单位

- 所有数值带单位；长度 m，时间 s，速度 m/s（载具为 km/h），角度 deg（或 mil，已注明），质量 kg，生命 HP。
- `【待调参】`：游戏性初值，靠内部试玩/`balance-sim` 调。`【待测 → REFERENCE_MEASUREMENTS §x】`：需黑盒测量参考作品后校准的量（x 为占位，由 REFERENCE_MEASUREMENTS.md 作者回填章节号）。
- 未标注的数值：史实参数（见 §0.4）或硬规则（可直接实现）。
- 数据落地：所有数值最终进入 `/data/{weapons,roles,loadouts,vehicles,structures,abilities,maps,rules}/*.json`（`rules/` 含 M0 新增的 `respawn.json`、`bots.json`，另有 `GameMode::Sandbox` 仅供 M0，见 ARCHITECTURE §8.5.4b），**这些 JSON 是数值唯一真源**；本文是它们的设计依据与初值。若 JSON 与本文冲突，以 JSON 为准并回写本文。
- 模拟固定步长 30 Hz（Δt = 1/30 s ≈ 33.3 ms）。所有计时在服务器以 tick 计，本文以秒给出。

### 0.3 命名与 ID 约定

- 武器 ID：`{faction}_{name}`，如 `us_m1_garand`、`ger_mg42`。载具 ID：`us_m4a1_75`、`ger_panther_g`。兵种 ID：`rifleman`。loadout ID：`{faction}_{role}_{n}`，如 `us_rifleman_1`。
- 阵营代码：`US`、`GER`。队伍侧：`team_a`/`team_b`（运行时绑定阵营；首发固定 US vs GER，但规则不得硬编码阵营）。

### 0.4 史实数据可信度说明（诚实声明）

- 武器与载具的口径、弹容量、理论射速、初速、乘员、装甲厚度均取自作者对公开通用资料（标准军事参考书与博物馆资料）的记忆整理并取整，**本次撰写未对每一项联网逐项复核**。不同来源对同一参数常有 ±5–15% 差异（尤其初速取决于弹药批次/枪管长度、理论射速取决于型号与测量方式、装甲角度取决于测量基准）。
- 凡标"约"的值是区间中点取整。执行工程师落地 JSON 时，若发现与可靠来源冲突，以可靠来源为准，并在 `/data` 的 `source` 字段记录出处；这类修订不需要回到本文评审。
- **穿深**（§14）是"游戏标称值"：按 30° 倾角（偏离垂直）标准取整并结合游戏需要微调，不是严格的试验数据；同样标【待调参】。
- **复核要求（R8）**：本节所述史实参数须由专门任务按 `docs/REFERENCE_MEASUREMENTS.md` §6 的史料来源逐项复核 `/data` 中的武器与载具参数；**复核完成前，相关数值在 `/data` 中的状态一律为 `initial`**（不得视为已定稿）。
- 游戏性取舍：为让 2048 m 地图与 30 Hz 模拟可行，火炮射程（§15）、手雷抛距等做了**压缩**，文中已逐项说明。

## 1. 设计支柱与对局概览

### 1.1 设计支柱

1. **高致死率、低容错**：步枪躯干 2 发倒地、爆头一击毙命；没有"打半天不死"。位置、掩体、信息优于枪法。
2. **指挥链驱动**：Commander → Officer（小队长）→ 士兵。资源、重生点、火力支援都沿指挥链流转；个人英雄主义收益低。
3. **补给与重生网络是第二战场**：Garrison/Outpost 建得好、守得住，比多杀几个人更能决定战线。
4. **兵种互补**：每个兵种有不可替代的独有能力（医疗、建造、补给、标记、反装甲、压制）。
5. **有节奏的拉锯**：Frontline 模式 5 条战线逐步推进，任何时刻只有一条战线是"主战场"，保证 100 人聚焦。
6. **诚实的网页现实**：规则必须在 30 Hz 服务器权威 + 浏览器客户端预测下可实现；不依赖亚帧精度。

### 1.2 对局概览

| 项 | 值 |
|---|---|
| 人数 | 50 v 50（含 bot，真人优先） |
| 视角 | 第一人称为主；载具支持第三人称切换（仅驾驶/车长，炮手保持光学视角）【待调参】 |
| 模式 | Frontline（默认）、Assault、Skirmish |
| Frontline 时长 | 最长 90 min |
| Assault 时长 | 初始 20 min，每占一点 +8 min（上限 60 min）【待调参】 |
| Skirmish 时长 | 最长 25 min【待调参】 |
| 胜负 | 见 §3 |
| 一局后 | 结算页 30 s → 地图投票 30 s → 加载下一图 |
| 阵营 | 首发 US vs GER，1944–45 西线 |
| 地图 | Carentan（1944-06）、Omaha Beach（1944-06-06）、Foy（1945-01）；各自适配的模式见 §3.7 |

### 1.3 一局的典型节奏（Frontline）

| 阶段 | 时间 | 主要玩法 |
|---|---|---|
| 开局 | 0–5 min | 部署、Officer/Spotter 放置首批 Garrison（Engineer 建资源节点与工事）、Support 运第一批 Supply Crate、Commander 解锁 Airhead 之外的能力 |
| 争夺中线 | 5–25 min | 在中线（L3）据点上形成主战场，装甲首次出击 |
| 推进/反推 | 25–80 min | 一方占 L3 后前线推进到 L2/L4，旧 Garrison 失效、新 Garrison 建立、资源节点易手 |
| 终局 | 最后 10 min | 以占点数结算；快速攻击/防守 |

## 2. 游玩流程状态机

### 2.1 状态总览

```
BOOT → MAIN_MENU ⇄ SERVER_BROWSER → CONNECTING → TEAM_SELECT → DEPLOY → IN_MATCH
IN_MATCH 内部子状态：ALIVE ⇄ DOWNED → KIA → (DEATH_CAM) → DEPLOY …
MATCH_END → SCOREBOARD → (MAP_VOTE) → LOADING_NEXT → TEAM_SELECT 或 MAIN_MENU
```

客户端状态机（UI 层）与服务器会话状态（`PlayerSession.state`）一一对应。下表列出每个状态的**进入条件 / 退出条件 / 计时与限制**。

### 2.2 状态定义

| 状态 | 进入条件 | 退出条件 | 计时/规则 |
|---|---|---|---|
| `BOOT` | 打开页面 | 资源包 ≤ 8 MB 加载完 → `MAIN_MENU` | 超时 60 s 显示重试 |
| `MAIN_MENU` | 启动完成；或离开对局 | 点"服务器浏览器"→`SERVER_BROWSER`；"快速加入"→选最优服务器直接 `CONNECTING` | 未登录则用游客身份（昵称 3–20 字符） |
| `SERVER_BROWSER` | 主菜单进入 | 选服务器并"加入"→`CONNECTING`；返回→`MAIN_MENU` | 列表字段见 §2.3；刷新节流 ≥ 2 s |
| `CONNECTING` | 点击加入 | 握手成功 → 若服务器在 `IN_MATCH` 则 `TEAM_SELECT`；若在 `MATCH_END/LOADING` 则等待；失败 → 提示并回 `SERVER_BROWSER` | 超时 15 s；满员(100)则排队（队列上限 20，位序实时显示） |
| `TEAM_SELECT` | 首次入服；换队；新一局开始 | 选择阵营并通过平衡校验 → `DEPLOY` | 选择时限 60 s，超时自动分配到人数较少一方（§2.4） |
| `DEPLOY` | 选队后；KIA 后；对局开始时存活玩家重新部署（可选） | 点"出击"并满足出生条件 → `IN_MATCH.ALIVE`（在选定重生点出生） | 子步骤：小队→兵种→loadout→重生点，见 §2.5 |
| `IN_MATCH.ALIVE` | 出生完成 | 受伤致 HP ≤ 0 且未超杀 → `DOWNED`；超杀/爆头/爆炸致死 → `KIA`；主动"自杀"（按住 3 s，仅限被卡死时） → `KIA`；对局结束 → `MATCH_END` | 出生保护 3 s（见 §2.6） |
| `IN_MATCH.DOWNED` | 见 §7 | 被 Medic 救起 → `ALIVE`；流血耗尽/被击毙/放弃 → `KIA` | 见 §7 |
| `IN_MATCH.KIA` | 死亡 | 3 s 死亡镜头后 → `DEPLOY` | 个人重生计时见 §10.6 |
| `MATCH_END` | 胜负判定成立 | 3 s 慢镜 → `SCOREBOARD` | 全员冻结移动输入，可聊天 |
| `SCOREBOARD` | 对局结束 | 30 s 到 → `MAP_VOTE` | 展示 §18.4 数据 |
| `MAP_VOTE` | 结算页结束 | 30 s 到 → `LOADING_NEXT` | 3 个候选（当前图除外，随机取） |
| `LOADING_NEXT` | 投票完成 | 加载完成 → `TEAM_SELECT`（保留小队：见 §4.6） | 进度条 + 战术提示 |

### 2.3 服务器浏览器字段

名称、地图、模式、当前阶段（战线进度如 "L2/5"）、剩余时间、人数（真人/bot/上限）、延迟 ping、地区、规则标签（无 bot、锁密码）、版本。支持按地图/模式/人数/延迟筛选。无服务器时给"快速加入"。UI 版式属原创，参见 UI_SPEC.md。

### 2.4 阵营选择与平衡限制

- 上限：每队 50 人（真人+bot）；超出则该队不可选。
- **真人平衡规则**：设 `H_t` = 某队真人数。新玩家只能加入使 `H_t − H_other ≤ 2` 成立的队伍；若两队均满足则可自选。若 `|H_a − H_b| ≥ 3` 且目标队更多者，则选择被锁并提示"该队人数较多"。
- Bot 动态让位：真人加入某队时，该队 bot 会立即被移除一个（先移除人在 DEPLOY 状态的 bot，其次存活 bot，其次载具中的 bot 最后），保证"真人优先占位"。真人离开则 bot 在 10 s 后补位（以免抖动）。
- **换队限制**：
  - 加入对局后 3 min 内不得换队（防止侦察信息）；
  - 两次换队间隔 ≥ 10 min（`team_switch_cooldown = 600 s`）；
  - 换队须满足上面的平衡规则；
  - 换队时：当前存活角色立即 KIA（不计死亡）、退出小队、本局已获 XP 保留、Commander 身份取消；
  - 管理员强制换队（自动平衡，见 §19.1）不受冷却限制，但每名玩家每局最多被强制 1 次。
- 好友组队：队伍（Party）≤ 6 人，同时申请同阵营；若平衡规则不允许，则整队排队等待而不是拆分。

### 2.5 部署界面（DEPLOY）

四步，均在同一界面可来回切换；"出击"按钮在四步全部有效时亮起。

1. **选择小队**：列表显示所有小队（类型、名称、人数/上限、队长、锁定状态、所在位置描述）。可"新建小队"（见 §4）。不加入小队 = "无编制"（Unassigned）：只能选 Rifleman，且只能在 HQ / 据点（Strongpoint）重生点出生，无法用 Garrison/Outpost。**小队必须有队长，Unassigned 玩家不占队长位。**
2. **选择兵种**：显示 14 个兵种中在该小队可选的项，灰显理由（名额已满 / 人数不足 / 未解锁 / 该队该兵种已满额，见 §4.4）。
3. **选择 loadout**：该兵种在该阵营的 loadout 列表（§5.3），显示解锁等级与预览，未解锁的灰显。
4. **选择重生点**：地图 + 列表显示当前所有可用重生点及其状态（可用/满/被封锁/冷却中）和**各自的预计出生时间**（§10.6）；默认高亮最靠近前线且可用者。

部署界面内允许：查看战术地图、聊天、语音（队内频道）、查看服务器信息、Commander 在此界面也可操作指挥面板（§13）。

### 2.6 出生与出生保护

- 出生位置：重生点周围 8 m 内随机不重叠的点（服务器检查 0.4 m 半径球体无碰撞）。
- **出生保护**：3 s 内伤害 ×0.0（不可被伤害），但移动、射击任一发生就立即取消（以不可利用为原则）；且保护仅在非前线重生点（HQ、Strongpoint 内部、Airhead 内部）有效，Garrison/Outpost/OP 不给保护。【待调参】
- 出生后立即获得所选 loadout 的满额弹药。Medic 额外携带绷带（§7）。

### 2.7 重新部署（主动）

存活玩家可在 HQ、本方 Strongpoint、Garrison 的 15 m 内按住 `重新部署` 键 2 s 回到 `DEPLOY`（旧角色离场，不算死亡，无重生等待），随后按平常流程出生，**但需遵守换兵种冷却**：同一玩家 30 s 内至多更换 1 次兵种/loadout【待调参】。

### 2.8 断线与重连

- 断线 90 s 内可凭会话 token 重连并**保留原角色状态**（位置、血量、弹药）。若断线期间角色被击倒/击杀，则重连后处于对应状态。
- 超过 90 s：角色移除，小队中该槽位空出，队长则按 §4.5 自动移交。
- 同一账号/IP 同时只能占 1 个席位。

## 3. 模式规则

### 3.1 通用术语与结构

- **Strongpoint（据点）**：地图上预设的可争夺点，由一个圆形占领区（半径 R_sp）定义，圆心有可视化地标（旗杆/无线电站）。
- **Sector（分区）**：地图被划分为 N 个互不重叠的多边形区域，每个 Strongpoint 属于一个 Sector。Sector 的所有权随其 Strongpoint 的所有权而定（见 §3.3.5）。资源产出、Garrison 建造成本、封锁区都按 Sector 计。
- **占领进度 `p`**：对每个 Strongpoint，记录 `p ∈ [−100, +100]`。+100 = 完全属于 A 队，−100 = 完全属于 B 队，0 = 中立。所有权状态：`p = +100` → 归 A；`p = −100` → 归 B；其余为"中立/争夺中"（该 Strongpoint 的**上一任所有者**保留"原属方"标记 `last_owner`，用于重生点与资源逻辑，直到 p 越过 0）。

### 3.2 占领速度公式（所有模式通用）

对一个 Strongpoint，每 tick 统计半径 R_sp 内的：

- 每队**有效人数** `n_A`、`n_B`：计入条件——存活、非倒地、非载具内（见下）、距圆心水平距离 ≤ R_sp 且高度差 ≤ 6 m。载具内：装甲载具的乘员**不计入**（防止坦克独占点）；运兵载具（卡车/半履带/吉普）内的乘客**不计入**；驾驶员不计入。
- 差值 `d = n_A − n_B`（正 = A 占优）。若 `d = 0` → **僵持**，`p` 不变。

有效人数权重（递减）：

```
eff(d) = min(|d|, 4) × 1.0 + max(0, min(|d|, 10) − 4) × 0.5     # 上限 10 人净优势，之后不再加速
rate   = k_cap × eff(d) × sign(d)       # 单位 %/s
p      += rate × Δt
p      = clamp(p, −100, +100)
```

- `k_cap = 0.20 %/s`（单个净优势人头）【待调参 / 待测 → REFERENCE_MEASUREMENTS §capture】。
- 示例：净优势 10 人 → eff = 7，rate = 1.4 %/s，把 p 从 −100 推到 +100（共 200）需 ≈ 143 s；净优势 3 → 0.6 %/s ≈ 333 s；净优势 1 → 0.2 %/s ≈ 1000 s（有效地不可能）。
- **回弹**：若半径内两队都没人（`n_A = n_B = 0`），且 `|p| < 100`，则 `p` 以 `0.15 %/s` 向**原属方 `last_owner`** 的方向回归（中立未曾被占的点则不回弹）。
- **占点完成**：`p` 到达 ±100 的一刻，所有权变更，触发 `StrongpointCaptured` 事件（分数、重生点处理、提示音）。
- **锁点（不可争夺状态）**：Frontline 模式下，非"当前活动线"的 Strongpoint 对 `p` 的任何更新被忽略（§3.3.3），UI 显示锁图标。

### 3.3 Frontline 模式（对标品类的 Warfare 类拉锯模式）

#### 3.3.1 地图结构

- 地图沿一条**主轴**（由地图作者定义，通常东–西或南–北）划分 **5 条战线 L1–L5**：L1 在 A 队（US）一侧最深处，L5 在 B 队（GER）一侧最深处，L3 为中线。
- 每条战线定义 2–3 个**候选 Strongpoint**（`/data/maps/<map>.json` 中 `lines[i].candidates[]`，每个含位置、半径、Sector 多边形）。同一线候选之间沿垂直主轴方向分布（左/中/右），保证不同开局有不同战场。
- **开局随机**：服务器在对局开始前（`MATCH_INIT`）用 `seed = hash(match_id)` 从每条线的候选中均匀随机选 1 个，共 5 个激活 Strongpoint；种子写入对局元数据，保证重放一致。Sector 多边形相应取该候选配套的 Sector，使 5 个 Sector 无缝拼满地图（地图作者须保证任意组合都可拼满：每条线的候选 Sector 在主轴方向的边界对齐于固定"战线分界线"）。
- **地图作者约束**（写进地图验收清单）：任意两队的选点组合都应有 ≥ 2 条可行进攻路线；L3 候选之间相互距离 ≥ 300 m；同线候选间的路径距离差 ≤ 25%（避免某组合对一方过度有利）。

#### 3.3.2 中线开局

- 初始所有权：L1、L2 属 A（`p = +100`）；L4、L5 属 B（`p = −100`）；L3 中立（`p = 0`，`last_owner = none`）。
- **活动线集合** `Active`：开局仅 L3 可被争夺（解锁），其余锁。
- 每方起始 HQ 在各自的 L1 Sector 后方，距离 L1 据点 ≥ 200 m；HQ 内设 Supply Depot（§12.2）与载具刷新点（§14.6）。

#### 3.3.3 活动线与推进规则

定义（每 tick 在服务器重算，亦在每次 `StrongpointCaptured` 后重算）：

```
front_A = 最大的 k 使 L1..Lk 全属于 A（若 L1 也不属于 A 则为 0）
front_B = 最小的 k 使 Lk..L5 全属于 B（若 L5 也不属于 B 则为 6）
中立线  = 不属于任何一方的线（开局只有 L3，之后不再出现）
活动线 Active =
    { 中立线 }                     若存在中立线（front_B − front_A = 2）
    { L_front_A, L_front_B }       否则（front_B − front_A = 1，即相邻的一对）
```

- 开局：`front_A = 2`，`front_B = 4`，中立线 L3 → `Active = {L3}`。L2、L4 锁定。
- 一方占领中立线 L3（设 A）：`front_A = 3`，`front_B = 4` → `Active = {L3, L4}`。A 可进攻 L4（敌所有），B 可反攻 L3（夺回，使 L3 归 B）。
- 任一活动线易手后立即重算。例：B 夺回 L3 → `front_A = 2`，`front_B = 3` → `Active = {L2, L3}`。例：A 占领 L4 → `front_A = 4`，`front_B = 5` → `Active = {L4, L5}`。
- 非活动线上的 `p` 更新被忽略（锁点），UI 显示锁图标，也不计占领分。
- 一方占领全部 L1..L5（即 `front_A = 5`）→ **立即获胜**。对 B 对称（`front_B = 1`）。
- 这样任何时刻活动线数为 1 或 2，且始终相邻，保证 100 人聚焦在一片战场。
- **防刷分**：同一据点 90 s 内被反复易手，后续易手不计 Offense 分（§18）。

#### 3.3.4 胜负

1. **全占决胜**：一方持有全部 5 条线 → 立即获胜（`victory_reason = full_control`）。
2. **时间到**：90 min 到达时，比较持有的线数；多者获胜（`time_limit_lead`）。
3. **平局决胜**（线数相同，例如 2:2 + 中立 1）：依次比较 ① 当前活动线上 `p` 之和的符号（谁的占领进度更大）；② 全局累计总分（§18.1）；③ 仍相同则平局。
4. 防止拖延：若最后 5 min 之内一方持有**最前线边界点**，则时间不延长；不存在加时（Assault 例外，§3.4）。

#### 3.3.5 Sector 所有权与相关效果

- Sector 属于其 Strongpoint 的当前所有者；中立点的 Sector 为"战区（Contested Zone）"。
- 所有者 Sector 决定：Garrison 建造成本（§10.2）、Supply 运输、资源节点可建性（§11）、Airhead 许可区（§10.4）、友方 Strongpoint 重生点可用性（§10.5）。
- 敌方 Sector：敌方持有的 Sector（含其据点）。

#### 3.3.6 战线切换时的重生点处理

当 Sector `S` 因 Strongpoint 易手而改变所有者（原 X → 新 Y）时，服务器执行：

| 对象 | 处理 |
|---|---|
| X 的 Strongpoint 重生点 | 失效；Y 的 Strongpoint 重生点启用（若 Y 在该点 `p = ±100` 且点周围 80 m 内无敌，见 §10.5） |
| X 在 `S` 内的 Garrison | 进入 `Condemned` 状态：停止接受重生，显示 30 s 倒计时（已在该 Garrison 出生等待的玩家被提示改选），**30 s 后销毁**（不返还 Supplies）；Y 方不能没收/复用它 |
| X 在 `S` 内的 Outpost | 保持（Outpost 属小队，随队长走）；但若超出 X 的 Sector 后在敌方 Sector 内，则**位置检查**：若距 Y 的 Strongpoint 中心 < 120 m 则立刻销毁，否则保留 |
| X 在 `S` 内的资源节点 | 立即销毁（并给 Y 一次 +50 Manpower 战利品奖励，仅限 Manpower 节点已建者；其它类型无）【待调参】 |
| X 在 `S` 内的工事（铁丝网、障碍等） | 工事**不易主**：保持 X 所有直到被摧毁；Y 的玩家可破坏 |
| X 的 Airhead | 保持直到自然过期 |
| Y 的 Garrison（本就在 S 内的敌后渗透） | 若 Y 在 S 内曾在 X 区放置过 Garrison，它现在自动变为"己方 Sector"成本；不退款 |
| 载具 | 不变 |

同时全队收到全屏横幅 + 战线推进音提示；Commander 与队长地图出现新的"前线边界"高亮。

### 3.4 Assault 模式（对标品类的 Offensive 类进攻模式）

- **非对称**：进攻方（Attacker）逐段推进，防守方（Defender）固守。阵营在每局开始前由地图配置（Carentan：US 攻；Omaha：US 攻；Foy：US 攻（史实：1945-01-13 美军 506th PIR 攻 Foy，以 MAPS §5.6 为准））；每局结束后若连续两局同图则互换。
- **结构**：同样 5 条线 L1–L5 与候选点（规则同 §3.3.1，开局随机），但**方向性固定**：进攻方从 L1 起，防守方持有 L2–L5（L1 为攻方 HQ 区，已属攻方）。**仅"当前目标点"（next uncaptured line）活动。**
- **每段目标**：进攻方占领当前线的 Strongpoint（`p` 从防守方 −100 推到 +100，规则 §3.2，进攻方净人数差为正）→ 成功后：
  - 该线属攻方，目标推进至下一线；
  - **加时**：计时器增加 `+8 min`（`capture_bonus`，上限总剩余 60 min）；
  - 防守方在该 Sector 的 Garrison 按 §3.3.6 销毁；
  - 防守方 HQ 位置可后撤：防守方获得该线 Sector 后方一个预设的**后撤 Rally 点**作为额外 HQ 重生点（地图数据 `fallback_spawn`），当前线之前的据点重生点失效。
- **计时**：初始 20 min（`initial_time`）。计时器归 0 时若进攻方未占完 5 线 → 防守方获胜。**阶段时限**：每个阶段（当前目标线）自激活起最长 `stage_limit` = 12 min【待调参】；到期仍未占领则按下述争夺窗口规则处理，窗口结束仍未完成 → 防守方获胜（不论总计时器余量）。进攻方占完全部 5 线 → 进攻方获胜。每个阶段时间用尽时，**当前阶段额外给 60 s 争夺窗口**：若此时进攻方 `p > 0` 且仍在占领区内，则计时到该占领完成或回落到 0 才结束（最多再延长 90 s）【待调参】。
- **防守方限制**：
  - 防守方不能在已被攻占的 Sector 内建造 Garrison；
  - 攻方不能在尚未占领的 Sector 内建造 Garrison（但 Outpost / OP / Airhead 可，规则按 §10）；
  - 防守方的 Manpower/Munitions/Fuel 产出同 Frontline；攻方的资源节点仅能建在已攻占 Sector。
- **资源偏置**：进攻方起始资源 +25%；防守方每队 Garrison 上限 +2【待调参】。
- **胜负**：见上。无平局。

### 3.5 Skirmish 模式（小规模单据点）

- 默认 16 v 16，最多 25 v 25（真人+bot），地图使用单一据点及其周边小区域（对地图而言取一个子区域，边界硬墙/"出界警告"）。
- **单一 Strongpoint**，半径 R_sp = 60 m，位于地图中央；开局中立（`p = 0`）。
- **计分**：持有点（`p = ±100` 持续）的一方每秒 +1 分（`hold_score`）；先到 **600 分**（10 min 持有）获胜；或 25 min 时间到，分高者胜，相同则 `p` 符号较大者，仍同则平局。
- **精简规则**：无 Commander（HQ 提供固定能力，无资源）；无资源系统；Garrison 上限 3/队，Outpost 允许，Airhead 无；载具：每队起始刷新 1 辆轻型装甲 + 1 辆中型坦克 + 1 辆运输车，被毁后冷却 300 s 再刷；火炮无；兵种全开但每队 Sniper/Spotter 各最多 1；补给箱仍由 HQ Depot 提供。
- 小队：小队类型同 §4，但 Recon 小队最多 1。
- 重生：HQ 波次 15 s，Garrison 8 s 个人冷却，Outpost 12 s。

### 3.6 占领区 / 据点强点半径参考

| 项 | 值 |
|---|---|
| Frontline Strongpoint 占领半径 R_sp | 地图数据设定，**默认 50 m**，范围 35–70 m【待调参】 |
| Skirmish 单点半径 | 60 m |
| Strongpoint 重生点解锁半径（封锁） | 敌人在据点中心 80 m 内即封锁该点（§10.5） |
| 地标高度判定 | 垂直差 ≤ 6 m 视为"在区内"（含二楼/高地） |
| 争夺区外延警示 | 占领区外 20 m 内有敌占点中的情况，UI 以圈脉动提示 |
| 占领进度显示 | 地图与 HUD 上方：双色进度条，A 色 / B 色；p 变化方向箭头 |

## 4. 编制

### 4.1 小队类型

| 类型 | 人数 | 队长要求 | 说明 |
|---|---|---|---|
| Infantry Squad（步兵小队） | 1–6（上限） | 可由 Officer 兵种担任；无 Officer 时队长是任一兵种 | 每队 ≤ 6 人/队，**数量不限**（受每队 50 人总数约束） |
| Armor Crew（装甲车组） | 1–3（上限） | Tank Commander 为队长 | 最多 4 个/队【待调参】；成员只能是 Tank Commander + Crewman |
| Recon Team（侦察组） | 1–2（上限） | Spotter 或 Sniper 均可为队长；队长必须为 Spotter（若有 Spotter） | 最多 2 个/队 |
| Commander | 1 | — | 每队 1 人；由第一个申请者在 DEPLOY 中占据；可被队内投票罢免（§19.3） |

**编制是上限而非固定构成（R2）**：每队总人数 ≤ **50**（含 Commander 1）；步兵小队每队 ≤ 6 人、小队数量不限；装甲车组 ≤ 3 人、每队最多 4 个【待调参】；侦察组 ≤ 2 人、每队最多 2 个；Commander 1。不再规定"6×6 + 3×3 + 2×2"之类的固定编制；各类小队按玩家实际需要创建，总人数超过 50 的真人只能排队。允许**无小队的散兵**（Unassigned，功能受限，见 §2.5）。

### 4.2 小队命名

- Infantry：Alpha、Bravo、Charlie、Delta、Echo、Foxtrot（北约拼写字母，通用词）；
- Armor：Armor-1、Armor-2、Armor-3；
- Recon：Recon-1、Recon-2；
- 队长可在创建时附加 ≤ 16 字符的自定义后缀（敏感词过滤）。

### 4.3 小队创建 / 锁定 / 踢人 / 队长移交

- **创建**：任何未入队玩家在 DEPLOY 中点"新建小队"，选类型；创建者自动成为队长；每队同类型小队已满则不可建。限制：每人每分钟最多创建 2 次。
- **加入**：未满且未锁定即可加入；新加入者不可选择已满额的兵种。
- **锁定（Lock）**：队长可锁定小队，锁定后只能由队长邀请（Invite）进入；解锁随时。队长离开时自动解锁并移交。
- **踢人（Kick）**：仅队长；被踢者 5 min 内不能重新加入该小队（本局内按队伍记录）；每分钟最多踢 3 人；服务器记录踢人理由（可选）。
- **队长移交**：
  - 主动移交：队长选择成员 → 对方确认（10 s 超时）；
  - 自动移交：队长离线 / 离队 / KIA 后未部署超过 120 s / AFK（§19.2）→ 优先给 **Officer**，其次本局累计得分最高的成员，再次加入最早的成员；
  - 小队无人则自动解散。
- **小队 ID 与位置**：小队 ID 在局内固定，但队名可被回收。

### 4.4 兵种名额与解锁人数限制

**每小队每兵种上限**（Infantry Squad，满 6 人）与**解锁所需小队人数**（小队当前人数 ≥ 阈值才可选择该兵种；含自己）：

| 兵种 | 每小队上限 | 解锁所需小队人数 | 全队上限 | 备注 |
|---|---|---|---|---|
| Officer | 1 | ≥ 2 | 不另设（每个步兵小队 1，随小队数量） | 且仅该小队队长可选 |
| Rifleman | 6 | 1 | 不限 | |
| Assault | 2 | 2 | 12 | |
| Automatic Rifleman | 1 | 3 | 6 | |
| Medic | 2 | 2 | 12 | |
| Support | 1 | 3 | 6 | |
| Machine Gunner | 1 | 4 | 6 | |
| Anti-Tank | 1 | 3 | 6 | 全队同时 AT 武器上限另见 §6.9 |
| Engineer | 1 | 3 | 6 | |
| Tank Commander | — | 仅 Armor Crew | 4（= 车组数上限）【待调参】 | 每 Armor Crew 1 人，队长 |
| Crewman | — | 仅 Armor Crew | 8（= 车组数上限 × 2）【待调参】 | 每 Armor Crew 至多 2 人 |
| Spotter | — | 仅 Recon Team | 2 | 每 Recon Team 1 人 |
| Sniper | — | 仅 Recon Team | 2 | 每 Recon Team 1 人 |
| Commander | — | 仅 Commander 席位 | 1 | |

规则细节：

- 阈值随小队人数动态变化：若人数下降到阈值以下，已选该兵种的玩家**当前存活者不被强制换**，但其 **下次部署**必须换（`role_valid_on_deploy` 重检）。
- 小队总计 6 人时的"标准配置"例：Officer、Medic、Support、Anti-Tank、Rifleman、Machine Gunner（合法）。
- 兵种限额是**按队计**的硬上限：全队 Machine Gunner ≥ 6 时，任何小队都不可再选。
- Unassigned 玩家只能 Rifleman。

|---|---|---|
| 放置小队标记（Move/Attack/Defend/Hold） | ✓ | ✗ |
| 放置 Outpost | 仅 Officer 兵种的队长 | ✗ |
| 接受 Commander 的命令 | ✓ | 只读 |

| 邀请/踢人/锁定/移交 | ✓ | ✗ |

### 4.6 局间小队保留

下一局加载后，原小队若仍有 ≥ 2 名真人且仍在该服务器，则自动重建同类型小队（队长不变），但阵营可能被自动平衡移出；玩家可手动退出。

### 4.7 人数不足时的 bot 编制

Bot 按 §20.2 规则自动按编制填入：Commander bot 仅当真人未占用；每个 Infantry Squad 由 1 名队长 bot + 若干士兵 bot 组成；装甲/侦察 bot 小队最少 1 个 Armor、1 个 Recon 按需开启。真人始终拥有优先占位权。

### 5.2 兵种等级（1–10）

- 每个兵种独立计 **Role XP**，用于解锁该兵种的 loadout。
- 累计所需 Role XP：`XP(n) = 125 × n × (n − 1)`（n = 目标等级）。即 L2 = 250、L3 = 750、L4 = 1500、L5 = 2500、L6 = 3750、L7 = 5250、L8 = 7000、L9 = 9000、L10 = 11250。
- Role XP 来源：在该兵种存活期间获得的分数（§18.2）；其中该兵种"本职"行为加成 ×1.5（例如 Medic 救起、Support 补给、Engineer 建造）。
- 兵种等级对**战斗力无直接加成**，只解锁 loadout 与外观（无付费内容，A1）。初始所有兵种 1 级；Commander 兵种等级以指挥分数计。
- 账号等级（§18.3）为总 XP，与兵种等级独立。

### 5.3 通用装备规则

- 所有步兵基础携带：**野战绷带 ×2**（Medic ×6）、**1 个战术头盔**（视觉，影响头部伤害，§6.6）、**1 把近战**（刺刀/匕首/工兵铲视兵种，§6.8）。
- 弹药数记法：**N 弹匣/夹（含枪内一个）**，如 "Garand 8 发/夹 ×9" = 枪内 8 发 + 备用 8 夹 = 共 72 发，枪内算在内。
- 手雷栏位：最多 2 种，如 `Mk2 ×2 + M18 ×1`。Tool 栏位：1 个。
- 所有 loadout 在重新部署（DEPLOY）时选择；补给后弹药回满该 loadout 的初始配置，不会超出。

### 6.4 弹道模型

**弹丸与服务器模拟**

- 所有枪弹为**服务器权威弹丸**，每 tick 做一次线段扫掠（swept raycast）：弹丸位置 `x_t → x_{t+Δt}` 的线段对世界/实体做命中检测。服务器以内部子步 4 次/tick（等效 120 Hz）积分重力与阻力，保证高初速弹丸的下坠与阻力精度。
- 客户端以同一份 sim 代码预测弹道（曳光与命中反馈），命中结算以服务器为准；延迟补偿（命中回溯 ≤ 250 ms，见总纲 §3 网络）对**发射时刻**的目标位置回溯，弹丸继续在**当前世界**中飞行（不回溯弹丸路径上的动态实体，只回溯目标命中盒）。

**运动方程**（每子步 `h = Δt/4`）：

```
a = (0, −g, 0) − k_drag · |v| · v          # k_drag 单位 1/m
v += a · h
x += v · h
子弹寿命：飞行 > 4 s 或速度 < 150 m/s 即销毁（高抛不致命）
```

**飞行时间（TOF）**：对着不同距离的近似值（真空估算，阻力使其略大）：`t ≈ (e^{k·x} − 1)/(k·v0)`。参考值：850 m/s 的步枪 300 m ≈ 0.40 s、600 m ≈ 0.95 s；MP40 380 m/s 的 100 m ≈ 0.30 s。

**弹丸阻力系数**（由 `k = ρ·Cd·A / (2m)`，ρ = 1.225 kg/m³，取整，【待调参】）：

| 弹药 | m (g) | 直径 (mm) | Cd | `k_drag` (1/m) |
|---|---|---|---|---|
| .30-06 M2 ball | 9.7 | 7.8 | 0.25 | 0.00075 |
| 7.92×57 s.S. | 12.8 | 8.2 | 0.27 | 0.00068 |
| 7.92×33 Kurz | 8.1 | 8.2 | 0.30 | 0.00120 |
| .30 Carbine | 7.1 | 7.85 | 0.35 | 0.00150 |
| .45 ACP | 14.9 | 11.5 | 0.40 | 0.00170 |
| 9×19 | 8.0 | 9.0 | 0.40 | 0.00200 |
| .50 BMG | 43 | 12.7 | 0.30 | 0.00055 |

**示例**（M1 Garand 853 m/s，k = 0.00075）：500 m 处速度 ≈ 853·e^{−0.375} ≈ 586 m/s，飞行时间 ≈ 0.72 s，重力下坠 ≈ 0.5·9.81·0.72² ≈ 2.5 m（瞄具须补偿）。

> **更正注记（M0-013）**：上式用 ½gt² 估算下坠（≈ 2.54 m），未计阻力与重力的耦合（阻力使水平速度衰减、飞行时间变长，但按 §6.4 的运动方程积分时竖直方向的下坠并不等于 ½gt²），数值偏大。按本节积分法（半隐式欧拉，4 子步/tick）实测 500 m 下坠约 **2.24 m**，高精度 RK4 参考约 **2.20 m**（两者相差约 2%），与 `crates/sim` 的实现和 `ballistics_vs_reference` 测试一致；上面的 2.5 m 仅是量级示意，瞄具补偿一律以服务器弹道表（积分结果）为准。

**瞄具零点（Zero）**：每把步枪的瞄具默认**零距离 100 m**；可在 ADS 中按键循环 100/200/300/400/500/600 m 分划（仅 Sniper 与瞄准镜枪有全程分划；机械瞄具枪的表尺仅 100/300 两档）。瞄具分划实现 = 枪管俯仰补偿角 `θ = atan(下坠/距离)`，由服务器按弹道表预计算。

**曳光弹**：MG 与自动步枪每 5 发 1 发曳光（可见）；其余无曳光。曳光为纯视觉。

### 6.5 后坐与散布模型

每把武器的后坐由三部分叠加：**视角后坐（kick）**、**弹道散布（spread）**、**武器摆动（sway，仅狙击与 MG 未部署时）**。

```
每发：
  view_pitch += vkick_deg × stance_recoil × (1 ± 15% 随机)
  view_yaw   += N(0, hsigma_deg) × stance_recoil
  bloom      += bloom_per_shot_deg
停止射击 recoil_delay_s（默认 0.12 s）后：
  view_pitch、view_yaw 以 recov_deg_s 速度回落到射击前（不超过累积量的 60% 自动回落，剩余 40% 留给玩家手动下压）
  bloom 以 bloom_decay_deg_s 衰减
弹道方向 = 视线方向 + 在半角 θ_spread 的圆锥内均匀随机
θ_spread = (θ_base_hip 或 θ_base_ads) × stance_spread × move_spread × supp_spread + bloom
```

其中 `stance_recoil`、`stance_spread` 见 §9.5；`move_spread`：静止 1.0、走 1.5、跑 2.5、冲刺不可射击；`supp_spread` = 1 + 1.5·(S/100)（压制，§8）。

**穿透计算**（子弹沿射线依次穿过多层）：

```
P = pen_power
for each 材质层 (thickness_mm t, cost c):
    need = t × c
    if P < need: 弹丸停止（部分嵌入：可对该层造成 damage）；break
    P -= need
    D_dealt *= max(0.25, P / pen_power)       # 穿透后伤害按剩余比例衰减，最低 25%
    方向偏转：在 ±1.5°（硬材质）/ ±0.5°（软材质）内随机
最多穿透 2 层；穿透过的弹丸不再造成穿透后的"二次头部判定"
```

- 身体命中后不再触发穿透继续（简化）；"穿身击中身后的人"在 ≥ 150 pen 弹药且前者为非头躯干时发生，伤害 ×0.5。
- 服务器每个弹丸最多检测 2 次穿透以防卡顿。

- 只有 Medic 能救起；其他兵种可以**包扎倒地者**使流血停止（2.5 s，消耗绷带，不恢复 HP）——此举让倒地者 `downed_hp` 不再流失，但仍需 Medic 救起。该规则让无 Medic 的小队能"保住"队友 80 s 以上。【待调参】

## 8. 压制（Suppression）

压制是**纯玩家体验效果 + bot 行为输入**，不改变伤害，只增加不确定性与风险。

### 8.1 触发条件

对**每颗敌方子弹**，服务器计算弹丸路径与目标头部（头部上方 0.2 m 到脚下 0.2 m 的胶囊轴线）的最近距离 `d`（只统计未命中的弹丸；命中者另有受击反馈）。

```
if 弹丸属敌方 and d ≤ d_max（默认 5.0 m）:
    s = caliber_weight × (1 − d / d_max)^1.2 × bullet_speed_factor
    S += s      # 玩家的压制值 ∈ [0, 100]
```

| 来源 | `caliber_weight` | 说明 |
|---|---|---|
| 手枪弹、9 mm、.45 ACP | 0.8 | |
| .30 Carbine、7.92×33 | 1.5 | |
| 7.92×57、.30-06（步枪） | 2.2 | |
| MG（7.92×57/.30-06 机枪射击） | 2.8 | 机枪射速高，累积快 |
| .50 BMG（载具机枪） | 6.0 | |
| 坦克/炮弹近失 | 见爆炸 | |
| 爆炸（手雷/炮弹/炸弹） | `S += 40 × (1 − r/R_supp)²`，`R_supp = 15 m`（炮弹 25 m） | 无视线要求，但被墙隔挡则 ×0.5 |

- `bullet_speed_factor` = `min(1, v/500)`（低速弹压制较弱）。
- 友军子弹不压制（但友军爆炸会）。
- 同一发子弹只触发一次；一次 tick 内多弹合并计算，避免精度问题；服务器最多每 tick 为一名玩家处理 12 发。

### 8.2 累积与衰减

```
S ∈ [0, 100]
受压制后 0.5 s 内不衰减（"压制窗口"）
之后：dS/dt = −(6 + 0.12·S)        # 单位 /s，S 越大衰减越快
姿态衰减修正：趴下 ×1.3，蹲 ×1.15，立 ×1.0，在掩体后（对射线被障碍阻挡）×1.4
Medic 等 Support 不提供解压；Rally 效果见 §13.8（累积 ×0.7）
```

示例：一挺 MG42（1200 rpm，每发 `caliber_weight` 2.8，`d = 2 m` → 每发 s ≈ 2.8×0.6^1.2 ≈ 1.5）持续扫射使 S 在 1.5 s 内到 ≈ 35；持续 4 s 到 80+。

### 8.3 效果

令 `e = S / 100`（0–1）。所有效果为平滑插值。

| 效果 | 公式 |
|---|---|
| 子弹擦过音/嗡声 | S > 5 时随机触发；音量 ∝ s |
| 画面模糊（径向 + 景深） | 径向模糊半径 `6·e` px（1080p 基准）；中心清晰区 `1 − 0.4e`；不低于 0.6 |
| 镜头晃动 | 随机位移幅度 `0.6°·e`，频率 12 Hz；**晃动同时叠加到视角与射击射线**（使压制对命中有实际影响） |
| 准星扩散 | `supp_spread = 1 + 1.5·e`（乘到盲射与 ADS 散布，§6.5） |
| 去饱和 | 屏幕饱和度 `1 − 0.55·e`；暗角 `0.6·e` |
| 移速 | `×(1 − 0.10·e)` |
| ADS 时间 | `×(1 + 0.30·e)` |
| 听觉 | 近距离语音与环境音降低 `3 dB·e`（AudioWorklet 低通） |
| "被钉死"（Pinned） | `S ≥ 85`：ADS 按键失效 0.5 s 后恢复；仅提示，不禁用射击 |

- 压制对**所有**兵种一视同仁；Sniper 开镜时更受影响（ADS 时间 +30%）。
- bot：压制值驱动其 AI 状态机（§20）：`S ≥ 30` 进入"找掩体"，`S ≥ 60` 尝试后撤或匍匐。

### 8.4 反刷分

压制本身不给分；"压制分"仅在被压制者 5 s 内被队友击杀时，给压制者 +3 分（`suppression_assist`），避免刷空射。

### 9.4 探身（Lean）

### 10.5 HQ 与 Strongpoint 重生点

- **HQ**：每队 1 个（Assault 防守方后撤会增加，§3.4）；半径 40 m 的出生区；**保护区**半径 150 m：敌方玩家进入后 3 s 警告，之后每秒受 40 HP 伤害（炮击模拟）；HQ 内设 Supply Depot（§12.2）、载具刷新点（§14.6）、重新部署点。
- **Strongpoint 重生点**：位于据点后方（地图数据设定一个固定的出生坐标，距据点圆心 ≥ 60 m）；可用条件：①本队持有（`p = ±100` 且对本队有利）；②据点圆心 80 m 内无存活未倒地的敌人；③Sector 非 Condemned；④Frontline 中，**最前线边界的己方据点**始终允许使用；⑤Skirmish 中据点本身无重生点（只有 HQ/Garrison/Outpost）。
- Strongpoint 重生点的出生保护：3 s。

### 10.6 重生计时与波次规则

**定义**：

- 每队有一个**全队波次计时器** `T_wave`，从对局开始起每 `15 s` 一个"波次 tick"（`t = 15, 30, 45, …`）。
- 玩家 KIA 的时刻 `t_kia`；死亡镜头 3 s；之后进入 DEPLOY。
- 玩家在 DEPLOY 点击"出击"并选定重生点 `P` 的时刻为 `t_pick`。

**出生时刻**：

```
ready_time(P) = t_kia + base_wait(P)
  base_wait: HQ = 5 s, Strongpoint = 5 s, Garrison = 8 s, Outpost = 12 s, Airhead = 5 s, OP = 15 s
对波次类（HQ、Strongpoint）：
  spawn_time = ceil_to_next_wave_tick( max(ready_time(P), t_pick) )
对其余类：
  spawn_time = max(ready_time(P), t_pick)
```

即 HQ/据点出生的等待在 5–20 s 之间（均值约 12.5 s），Garrison 8 s，Outpost 12 s，Airhead 5 s。

**附加规则**：

- **自杀惩罚**：出生后 20 s 内再次 KIA（含放弃），`base_wait` +5 s（仅当次）。【待调参】
- **同点洪水限制**：同一重生点 10 s 内出生人数 ≥ 8 时，之后出生者 +2 s。
- **重生点失效**：若选定的重生点在等待期间变为不可用，玩家收到提示并改选；若无选择，自动落到 HQ。
- **Commander 预选**：Commander 可设置"全队优先重生点"（推荐点，部署界面高亮，不强制）。
- **热身期加速**：预热阶段（§19.7）所有重生点的 `base_wait` ×0.5。【待调参】
- 以上全部数值【待调参 / 待测 → REFERENCE_MEASUREMENTS §respawn】。

### 10.8 防"重生杀"与出生安全

- 玩家在重生点出生时，若 10 m 内有敌方存活玩家且有视线，服务器将出生点向后偏移到最远可用的出生坐标；若仍有威胁，该 Garrison/Outpost 立即被判为封锁（但已出生者不受影响）。
- HQ 保护区对**敌方**玩家造成伤害（§10.5），对友方无影响。Strongpoint 重生点无保护区，但有 80 m 封锁规则。

### 10.9 登陆艇出生（`boat`，Omaha 进攻方专用）

- 仅在地图数据声明 `kind: "boat"` 的出生点的地图使用（Omaha Beach 的 Assault/Frontline 变体，MAPS §4）；防守方与其它地图不适用。
- 进攻方在“登陆阶段”（地图配置的前若干分钟，或直到海滩第 1 条线被占领）可选择登陆艇出生：按波次（初值 20 s 一波）把等待者放入艇内，航行 `transit_s`（初值 25 s，艇内玩家不可开火，仅受爆炸/迫击炮类伤害，枪弹无效）后到达滩头放下跳板，玩家出舱。【待调参】
- **出生保护**：在艇内与跳板放下后 3 s 内不受伤害，3 s 内开火/移动即取消（规则同 §2.6 出生保护，但对 boat 生效，与 Garrison 不同）。
- **不可被封锁**：boat 出生点不受 §10.2 的“封锁（Blocked）”与 §10.8 的“敌近距离偏移”规则影响；但艇被摧毁（地图脚本事件，HP 初值 2000，仅 Bombing/炮击/反坦克炮可损）则该艇本波作废，等待者自动改派到下一艘艇。
- 地图数据可限制 boat 的启用时段（`active_until: line_captured(L1)`）；失效后改用 HQ/Garrison/Outpost。
- 网络：`SpawnPointState.kind` 含 `boat`（ARCHITECTURE §6.8）。

### 11.1 三种战略资源

### 11.2 产出（每分钟结算一次，整分钟 tick，`t = 60, 120, …`）

```
income_X(per min) = base_X + sectors_held × sector_rate_X + nodes_X × node_rate_X
```

| 资源 | `base`（/min） | `sector_rate`（/min/ Sector） | `node_rate`（/min/个） | 上限（队） |
|---|---|---|---|---|
| Manpower | 30 | 6 | 25 | 1500 |
| Munitions | 12 | 3 | 10 | 800 |
| Fuel | 6 | 2 | 6 | 400 |

- 开局持有 2 个 Sector（Frontline：L1、L2 的 Sector）→ 起始产出 Manpower 42 / Munitions 18 / Fuel 10 每分钟；起始储备 **Manpower 200 / Munitions 80 / Fuel 40**。
- `sectors_held`：拥有的 Sector 数（本方 Strongpoint 已被占领的 Sector；中立线不计）。
- **每类资源节点上限**：每队 3 个（共 9 个）；每个 Sector 最多 1 个各类型节点（地图在每个 Sector 预设 3 个 `resource_site`，类型分别为 M/Mu/F）。
- Assault：进攻方起始储备 ×1.25（§3.4）。Skirmish：无资源系统。
- 所有数值【待调参 / 待测 → REFERENCE_MEASUREMENTS §economy】。

**示例**：双方都持 2 个 Sector、各建 2 个 Manpower 节点 + 1 个 Munitions + 1 个 Fuel：Manpower = 30 + 12 + 50 = 92/min，Munitions = 12 + 6 + 10 = 28/min，Fuel = 6 + 4 + 6 = 16/min。90 min 对局约累计 Manpower 8300（受上限与消耗约束）。

|---|---|

### 11.4 资源消耗与上限

- 各能力/载具的消耗见 §13、§14.6。资源不足则按钮灰显。

- 溢出：超过上限的收入丢弃，UI 在资源条显示"已满"。

## 12. 补给与建造

### 12.1 Supplies 概念

- **Supplies（补给点）** 是**建造专用**货币，装在 **Supply Crate** 里（物理物体，1 箱 = 100 Supplies）。与战略资源 Manpower/Munitions/Fuel **不同池**。
- 建造时，系统自动从工地 **15 m** 内所有 Supply Crate、卡车/半履带的**车载补给**中扣除；不足则禁止开工。

### 12.2 Supply Crate

| 放置 | Support 在地面放下，放下时间 1.5 s；每队地面上 Supply Crate 总数 ≤ 40（超出时最早的消失） |

### 12.5 补给流程示例

1. HQ Depot 生成 Supply Crate → Support 搬运（或装卡车）→ 到前线。

3. 前线耗尽后，Support 再补；Commander 可呼叫 Supply Drop 补空窗。

- Depot 库存不累积到溢出，库存满则不再生成。

## 13. 指挥官能力

### 13.1 通则

- 只有**存活且未倒地**的 Commander 可以释放；Commander 死亡/倒地时，进行中的能力继续，但无法下新指令；冷却持续计时。
- 地图点选：Commander 在战术地图上点选目标，部分能力需要方向（拖拽设置）。
- **资源**：下达时一次性扣除；取消（飞机到达前）返还 50%。
- **空中支援锁定**：全队任何两次空中支援（Bombing/Strafing/Precision/Recon/Supply Drop/Ammo Drop/Airhead）之间有 **10 s 全局锁**；同时在空飞机 ≤ 3。
- **友军保护提示**：所有空袭目标在友军 25 m 内时，UI 显示"危险近距"警告但仍允许（友军伤害按 `ff_mult` 的爆炸 0.7）。
- **敌方警告**：Bombing Run、Strafing Run、Precision Strike 抵达前 15 s，对敌方播放防空警报，并在地图上显示以目标为中心半径 200 m 的模糊环（不暴露方向）。Supply/Ammo Drop 与 Recon Flight 对敌无提示（仅飞机声音，距离 < 400 m 可听）。
- 无 Commander 的队伍：Commander bot 接管（§20.1）；如果没有 bot 与真人，能力不可用。
- 以下数值全部【待调参】，其中延迟与冷却的"体验长度"【待测 → REFERENCE_MEASUREMENTS §commander】。

### 13.3 Supply Drop / Ammo Drop

- Commander 点选落点（须在本方或战区 Sector；距敌方据点圆心 ≥ `R_sp + 80 m`）。
- 运输机沿固定航线飞过，空投 4/2 个箱（带降落伞；投放高度 120 m，降落伞下降速度 6 m/s ≈ 20 s 落地；下降期间可见但不可被击毁、不可交互，落地后才可交互）【待调参】；落点在设定圆内随机；落地时发出烟雾标识（Supply = 彩色烟雾 20 s；Ammo = 另一种颜色）。
- 箱子可被敌人拾取（Supply 可搬运；Ammo 可使用）：不加限制。
- 空投机不可被击落（v1 无防空）。

### 13.4 Bombing Run

- 点选**两个点**定义条带方向与长度（长度固定 400 m，以第一点为中心沿方向延伸 ±200 m），条带宽度 70 m。
- 飞机到达时间 = 点击后 45 s（敌方警告出现在 T−15 s）。
- 3 架轰炸机依次飞越，每架在 6 s 内每 0.33 s 投 1 枚炸弹，总计 18 枚随机落入条带。
- 每枚炸弹：对步兵 `Dmax 400 / R 14 m`；对载具直击（≤ 4 m）600 HP，近失 200 HP；对建筑 1500 HP；留下弹坑（地形变形，视觉）。
- 伤害公式同 §6.6 爆炸。

### 13.5 Strafing Run

- 点选两个点定义条带（长度 300 m，宽 14 m），敌方警告在 T−15 s。
- 2 机编队，沿条带飞越 3 s：每 0.025 s 一个落点，横向在条带内均匀随机；每个落点半径 1.8 m，对步兵 90 HP（中心）、对载具 25 HP（对 ≤ 20 mm 装甲有效）、对建筑 30 HP；每个落点压制半径 20 m（`S += 12`）。
- 对站立玩家在条带内的命中概率约 25–30%（期望值，设计目的：区域拒止而非必杀）。

### 13.6 Precision Strike

- 点选单点；一架俯冲轰炸机（US：P-47 类；GER：Ju 87 类）投放 1 枚大型炸弹；延迟 22 s。
- 爆炸：步兵 `Dmax 800 / R 22 m`；载具直击（≤ 5 m）1200 HP；建筑 3000 HP。
- 点选时显示 22 m 红圈；友军在圈内时标红提示。

### 13.7 Recon Flight

- 点选两个点定义条带（长 300 m，宽 120 m）。
- 飞机飞越 6 s，期间条带内所有**存活敌人**（含载具）在本队地图上以标记显示，位置实时更新，飞越结束后 12 s 内显示"最后已知位置"（逐渐淡出）。
- 对敌无警告，但飞机噪音可闻。
- 对隐藏的 Sniper（迷彩，§17.3）与 OP 同样有效。

### 13.8 Rally

- Commander 点选一个本方小队或一个地面点；3 s 后在半径 40 m 内的本方玩家获得 45 s 增益：冲刺速度 +10%、体力消耗 ×0.7、压制累积 ×0.7、HP 恢复到 60 的阈值提高到 80。
- 增益可见：头顶小旗标；对敌不可见。
- 可对多个小队连续释放，受冷却限制。

### 13.9 载具呼叫

- Commander 在指挥面板选择载具类型（受 §14.6 刷新规则限制：数量上限、冷却、资源），确认后 3 s 在 HQ 载具刷新点出现。
- **认领**：载具出现后 60 s 内未被小队认领则回收并全额返还资源（唯一口径）。Armor Crew 人数需求在**认领时**校验（§14.6.1）：认领者所在 Armor Crew 小队当前人数不足则认领失败；60 s 内无人成功认领即回收退款；已认领后乘员离队不影响载具。

### 13.10 指挥官 UI 与规则

- Commander 面板：资源条（含每分钟收入）、各能力按钮（冷却圈、资源不足灰显）、全队地图（友军 1 Hz 位置、小队位置）、小队列表、Command 频道按钮。
- Commander 发布命令（地图标记）：攻击/防守/进攻路线/请求火力支援；权限见 §16.5。
- 每名玩家只能是 Commander 一次：局中交接需要当前 Commander 主动让出或被投票罢免（§19.3）。
- **Commander 兵种等级**：由累计指挥分（能力命中获得分数）决定，对 loadout 有解锁（§5.4）。

## 14. 载具

### 14.1 通用模型

**数据文件**：`/data/vehicles/<id>.json`。每辆载具包含：史实信息（`historical`）、座位（`seats[]`）、装甲区（`armor_zones[]`）、模块（`modules[]`）、武器（`weapons[]`）、物理（`physics`）、资源成本与刷新（`spawn`）。

**载具生命值体系**：

### 14.4 穿深与装甲判定模型

#### 14.4.1 判定流程（对每发炮弹/火箭）

1. 弹丸线段与载具**外形碰撞体**相交，得到命中点、命中面法线 `n`、弹丸速度方向 `v̂`。
2. 命中区域识别：通过命中点所在的 `armor_zone`（顶点着色的区域 ID 映射）取得 `t`（板厚 mm）、`slope`（该区域倾角基准）。**实际入射角以命中面的几何法线为准**（不用表中倾角，除非区域是复合曲面）。
3. 入射角 `φ = acos(−v̂ · n)`（°，0° = 垂直命中）。
4. **弹种修正**：
   - AP/APCBC：`φ_eff = max(0, φ − 5°)`（弹头 normalization）。
   - HEAT：`φ_eff = φ`，不做 normalization。
5. **跳弹（Ricochet）**：AP 若 `φ_eff ≥ 68°`、HEAT 若 `φ_eff ≥ 75°` → 跳弹：弹丸沿镜面反射（衰减 60% 动能），不穿透，不造成结构伤害（对外露模块仍可能受 3% 冲击伤害）。**过匹配（Overmatch）**：若炮弹口径 ≥ 3×板厚（如 75 mm 打 9.5 mm 侧板），不触发跳弹，`φ_eff = min(φ_eff, 45°)`。
6. **等效厚度**：`t_eff = t / cos(φ_eff)`（上限 `t × 3`）。
7. **穿深**：`P(d) = P100 × (1 − drop × (d − 100)/100)`，`d` 为飞行距离（m），`d < 100 m` 时 `P = P100`；最小 `0.3 × P100`。HEAT 的 `drop = 0`。
8. **穿透判定**：`P(d) × U(0.95, 1.05) ≥ t_eff` → **击穿**；否则**未击穿**（Bounce/Stuck）。
9. **击穿后**：剩余穿深 `P_rem = P(d) − t_eff`（≥ 0）；对弹丸后续路径做内部检测（§14.4.4）。
10. **未击穿**：对该车体 `hull_hp` 造成 `3% × 结构伤害` 冲击伤害；对命中的**外部模块**（履带、炮管、车轮）如适用则按 §14.4.5。

#### 14.4.2 示例

- Sherman (M4A1) 对 Panther 车体前上：`t = 80`，`slope = 55°`；若水平命中，`φ ≈ 55°`，`φ_eff = 50°`，`t_eff = 80 / cos 50° = 124.5 mm`。75 mm M61（`P100 = 82`，距离 300 m：`P = 82 × (1 − 0.035×2) = 76.3`）→ 无法击穿；76 mm M62（`P100 = 115`，300 m：`108`）→ 无法击穿。需打侧面（50 mm/30°，AP 先做 5° normalization：`φ_eff = 25°` → `t_eff = 50 / cos 25° ≈ 55.2` mm）：75 mm M61 的 76.3 与 76 mm M62 的 108 均可击穿。
- Panther（KwK 42，300 m：`P = 140 × (1 − 0.018×2) = 135`）对 Sherman 车体前：`t_eff = 51 / cos(56°−5°) = 51 / 0.629 = 81` → 击穿；Jumbo（101 / 47° → `φ_eff = 42°`，`t_eff = 135.9`）≈ 135：临界，随机性 ±5% 决定。
- Bazooka（HEAT 90 mm）对 Tiger 侧：`t = 80` → 可击穿；对 Tiger 前上：`t_eff = 100 / cos 9° = 101` → 无法击穿。Panzerfaust（200 mm）对 Jumbo 前上：`t_eff = 101/cos 47° = 148` → 击穿。

#### 14.4.3 顶部与底部

- 顶部装甲（炮塔顶、车体顶）：`t` 取表值，倾角 90° 用垂直入射（炮弹自上而下，`φ` 接近 0°）；轰炸/炮弹对顶部使用 HE 穿深（`0.2 × 口径`）：Bombing Run 的 600 HP 直击视为击穿。
- 底部：地雷爆炸直接作用于履带/车轮模块与车体（§6.9.5），不走装甲流程。

#### 14.4.4 击穿后的内部损伤

```
dmg_pen = 结构伤害 × U(0.9, 1.1)
internal_len = 0.6 + P_rem / 40   # 米，上限 3.0
沿弹丸方向 internal_len 内的每个内部碰撞体（乘员、模块、弹药架）：
    乘员：伤害 = dmg_pen × 0.25；≥ 100 → KIA；同舱室其他乘员受冲击/破片伤害 dmg_pen × 0.08
    模块：伤害 = dmg_pen × 1.0
    弹药架：被命中时按弹药架殉爆概率检定（§14.5）
hull_hp -= dmg_pen × 0.5 + 模块伤害合计 × 0.2
```

- 对**软车辆**（Jeep/卡车/Kübel）：任何击穿（含枪弹）按软目标处理：伤害 = 武器伤害 × 0.4（直接作用于 `hull_hp`），乘员按其人体命中盒判定（开放车厢乘客可被直接击中）。
- 车体 `hull_hp` 归零 → **击毁（Knocked Out）**：见 §14.5.2。

- **M2 临时规则（规则指挥官，M3 由 Commander 面板取代）**：M2 阶段无 Commander 席位时，由服务器内的“规则指挥官”按固定节奏（初值：每 90 s 检查一次，各类载具位空闲且未达 §14.6.1 的数量上限/冷却/Armor Crew 条件时自动刷新一辆，不消耗资源池）【待调参】将载具刷新到 HQ 载具位；Crewman 在 HQ 认领（认领与回收规则同 §13.9）。M3 接入 Commander 面板后本条停用。

### 14.7 驾驶与武器操作

- 驾驶输入：W/S 油门/倒车、A/D 转向；坦克用差速转向；`Shift` 提速（至游戏最高速）；手刹。
- 炮手：鼠标瞄准；主炮与同轴机枪；`R` 切换弹种（切换需要重新装填 1.0 s，预装弹种可选）。
- 车长：舱盖开/关（开舱视野大但暴露，关舱视野受限：潜望镜前向 90° 视野）；可操作车顶机枪；车长可**接管炮手瞄准**（"车长优先"模式）。
- 载具内语音：车组频道（§16）。
- 载具弹药补给：靠近己方 Repair Station、补给卡车或 Ammo Crate；炮弹补给每发 40 弹药点。

**游戏压缩**：地图可玩区 2048 m × 2048 m，史实射程 11 km 超出地图数倍。游戏中使用**压缩射程**：三档装药的最大射程 `Rmax` = 800 / 1800 / 3200 m，初速 `v = √(Rmax · g)`，对应 88.6 / 132.9 / 177.2 m/s，**不模拟空气阻力**，弹道为抛物线。（史实炮弹初速与射程在本版为"装饰性史实信息"，不参与计算。）

### 15.2 阵地构建与资源

- 榴弹炮是 **HQ 附近地图预设的固定阵地**（Artillery Site，每队 2–3 个，位于己方后方；**开局即存在，无需建造**，R7）；由玩家操作。**Engineer 不建造榴弹炮**，也无 Supplies 建造成本。阵地被毁后的重置规则（冷却/是否原地复原）【待调参】，不新增建造项。
- **炮弹库存**：每门炮初始 24 HE + 8 烟雾；通过 **Shell Stock**（§12.4）补充：100 Supplies → 8 HE 或 4 烟雾；库存上限 48 HE + 16 烟雾。库存对炮手显示在 HUD。
- 阵地在被敌方**占领区**内的 Overrun：敌人 15 m 内持续 20 s 且己方 15 m 内无人，则炮被摧毁。

### 15.3 操作流程

1. **进入座位**：炮手（座位 1）与装填手（座位 2）。单人操作（仅炮手）时装填周期变长（见下）。
2. **目标数据**：当 Officer/Spotter/Commander 在地图放置 **Fire Mission 标记**后，炮手 HUD 显示：目标相对炮位的**方位角（°）、距离（m）**、推荐装药与**仰角**（见 §15.4 公式）。炮手可忽略推荐，手动操作。
3. **瞄准**：
   - 方位角：炮手转动炮身，转速 4°/s（可精调 0.1°/s 的"微调"键）；HUD 显示 0–360° 刻度环与数字（精度 0.1°）；
   - 仰角：转速 3°/s，范围 5°–85°；HUD 显示数字与刻度；
   - 装药（Charge）：1/2/3，装填手选择；
   - 弹种：HE/烟雾，装填手选择。
4. **装填**：装填手按住交互依次 "装弹 → 装药 → 闭锁" 共 3.5 s（计入循环）；
5. **开火**：炮手按下开火键，炮弹出膛；声光效果；炮口闪光向敌方暴露（见 §15.6）。
6. **循环时间**（装填+复位）：M2A1：6.0 s（2 人）/ 10 s（1 人）；leFH 18：7.0 s（2 人）/ 11.5 s（1 人）。无过热。
7. **观察者修正**：观察者（Officer/Spotter/Commander）可对已有 Fire Mission 发送**修正**：`向左/右 25/50/100 m`、`增加/减少 25/50/100 m`（相对原炮目线），UI 自动更新炮手的目标数据；观察者的双筒望远镜可以看到落点并报告误差（UI 显示落点相对标记的偏移量）。

### 15.4 距离-仰角换算

**低角射击**（默认）：`θ = ½ · asin(R / Rmax_c)`（°），`R` 为到目标水平距离，`Rmax_c` 为所选装药最大射程。需 `R ≤ Rmax_c` 且 `R ≥ R_min_c = Rmax_c · sin(2·5°)`（最小仰角 5°）。**高角射击**（越过障碍/山脊）：`θ_high = 90° − θ`，最大仰角 85°。飞行时间 `t = 2 · v · sin θ / g`。

对于目标与炮位**高度差 Δh**：玩家 HUD 的"推荐仰角"使用迭代求解（服务器给出，含 Δh 的抛物线）；本表为 Δh = 0 的基准。

|---|---|---|---|---|---|---|---|
| 1 | 800 m | 88.6 | 200 | 7.2° | 2.3 s | 82.8° | 17.9 s |
| 1 | 800 m | 88.6 | 400 | 15.0° | 4.7 s | 75.0° | 17.5 s |
| 1 | 800 m | 88.6 | 600 | 24.3° | 7.4 s | 65.7° | 16.5 s |
| 2 | 1800 m | 132.9 | 600 | 9.7° | 4.6 s | 80.3° | 26.7 s |
| 2 | 1800 m | 132.9 | 900 | 15.0° | 7.0 s | 75.0° | 26.2 s |
| 2 | 1800 m | 132.9 | 1200 | 20.9° | 9.7 s | 69.1° | 25.3 s |
| 2 | 1800 m | 132.9 | 1500 | 28.2° | 12.8 s | 61.8° | 23.9 s |
| 3 | 3200 m | 177.2 | 1000 | 9.1° | 5.7 s | 80.9° | 35.7 s |
| 3 | 3200 m | 177.2 | 1600 | 15.0° | 9.4 s | 75.0° | 34.9 s |
| 3 | 3200 m | 177.2 | 2000 | 19.3° | 11.9 s | 70.7° | 34.1 s |
| 3 | 3200 m | 177.2 | 2400 | 24.3° | 14.9 s | 65.7° | 33.0 s |

- 最小射程（`R_min = Rmax · sin 10°`）：装药 1 = 139 m，装药 2 = 313 m，装药 3 = 556 m。
- 玩家可见"射表卡"（UI 中的一张图，原创设计），也可使用纯手算；服务器按真实弹道积分结算，不做吸附。

### 15.5 弹药与伤害、散布

| 项 | HE | 烟雾 |
|---|---|---|
| 步兵伤害 | `Dmax 600 / R 14 m`（致命半径 ≈ 6 m），公式见 §6.6 | — |

**散布**（高斯，每发独立）：

```
σ_range  = 0.012 × R       # 纵向散布，R = 目标距离（m）
σ_lateral = 0.006 × R      # 横向散布
截断到 3σ
Registration（校射）：若一发炮弹落点距目标 ≤ 40 m 且被友方 Spotter/Officer 看到，则在随后 120 s、目标 100 m 内的同装药射击，σ ×0.7（鼓励校射）
```

例：R = 2000 m：σ_range = 24 m，σ_lateral = 12 m，致命半径 6 m → 首发通常不中，必须校射。【待调参 / 待测 → REFERENCE_MEASUREMENTS §artillery】

### 15.6 暴露与反制

- **友军误伤**：爆炸 ×0.7。

- **敌人信息防作弊（R3，与 ARCHITECTURE §6/§15 统一）**：服务器仅在敌方实体满足 **距离 ≤ 400 m 且（位于该玩家视锥 + 30° 余量内，或距离 ≤ 96 m）** 时才向客户端下发其精确状态；其余敌人一律不下发精确位置。被友军标记（§17.1）或侦察（§13.7）暴露的敌人**只下发地图图标**（1 Hz，位置量化到 5 m）。友军：最远 400 m 内按优先级下发，最低 2 Hz；更远的友军只走团队通道图标（1 Hz）。【待调参】（具体见 ARCHITECTURE.md 的 AOI 设计）

### 17.3 Sniper 隐蔽

- 迷彩服：被 bot 视觉检测距离 ×0.7；对人类玩家，模型对比度降低（不改变碰撞与命中盒）。
- Sniper 趴姿且静止 ≥ 3 s：被发现距离再 ×0.8（叠加后 ×0.56）；开火后 5 s 内恢复为 ×1.0。
- Spotter 与 Sniper 共享 OP 出生（§10.7），二人在 100 m 内时 Sniper 的开镜稳定性 +20%（sway ×0.8），模拟观察员协同。

### 18.2 经验与等级

- **Match XP** = 本局总分 × 1.0 + 胜负奖励（胜 +10%，负 +5%，平 +7%，需在局内 ≥ 5 min）+ 完整参与奖励（≥ 70% 对局时间）+100。
- **账号等级（1–100）**：累计 XP 需求 `XP_acc(n) = 400 × (n − 1)^1.5`（L10 ≈ 10800、L50 ≈ 137000、L100 ≈ 394000）【待调参】。账号等级只用于显示/个性化解锁（无付费，A1）。
- **兵种等级（1–10）**：见 §5.2；Role XP = 在该兵种存活期间获得的分数，本职行为 ×1.5（Medic 救起/包扎、Support 补给与搬运、Engineer 建造与修理、Spotter 标记助攻、Sniper 击杀、Officer 的 Outpost/Garrison 出生与小队行动、Commander 能力）。
- Role XP 记录进入局间存档（账号/匿名游客）。游客的进度保存在 gateway（以匿名 ID）与本地 token；未登录丢失 token 则丢失进度（诚实提示）。

## 19. 服务器规则

### 19.1 自动平衡

- **目标**：两队真人数差 ≤ 2（见 §2.4）。bot 填满剩余位置，使每队总数相同（≤ 50）。
- **检查**：每 30 s 检查；若 `|H_a − H_b| ≥ 4` 持续 90 s，则触发平衡：
  1. 向人数多的一队**弹出邀请**（"移到人数少的队伍可获得 +20% XP 本局"）；
  2. 60 s 内无人响应，则**强制移动**：优先选择**最近加入**、**不是小队长/Commander**、**不在小队中或小队人数 ≥ 2 以上最小的**、**本局得分最低**的玩家（不移动 Commander 与队长；不移动 90 s 内刚被移动的玩家；每名玩家每局最多被强制 1 次）；
  3. 移动被执行时，玩家的存活角色立即 KIA（不计死亡），收到"已被服务器重新分队"提示并进入 `TEAM_SELECT`（只能选目标队）。
- **局间重排**：新局开始前，按上局小队与分数进行"蛇形分配"，使队伍实力均衡，同小队尽量同队（§4.6）。
- 同一好友队伍（Party）不拆分。

### 19.2 友军伤害与 TK 惩罚

- 友军伤害系数见 §6.6（枪弹 ×0.5，爆炸 ×0.7，近战 ×0，碾压 ×1.0，坦克炮 ×0.5，自伤手雷 ×1.0）。
- **TK 记录**：友军击倒/击杀均记 1 次 TK（`tk_count`），保存 30 min。
- **受害者选项**：被友军杀死后弹出"原谅（Forgive）/ 惩罚（Punish）"，15 s 内选择；惩罚 = 加害者 `tk_strikes += 1`。
- **惩罚阶梯**：

| 条件 | 处罚 |
|---|---|
| 每次 TK | 分数 −30（Combat），Role XP 不扣 |
| `tk_strikes` = 2（10 min 内） | 警告，该玩家 5 min 内不能担任 Machine Gunner/Anti-Tank/Engineer/Crewman（高危武器）|
| `tk_strikes` = 3 | 该玩家被锁定在 Rifleman 5 min；载具无法认领 |
| `tk_strikes` = 5（本局） | 踢出服务器，30 min 冷却 |
| 明显恶意（车辆碾压友军 ≥ 3 次、炸药包炸 Garrison 等）| 管理员/投票封禁 |

- 友军载具被己方炮/炸弹击毁 + 乘员死亡：对炮手/车长记 TK；轰炸/炮击的 Commander 对友军伤害以 `ff_mult` 计算，不记 TK（但有警告）。
- 载具内乘员互相射击：枪弹/炮弹不伤害同乘员。

### 19.3 投票

| 投票 | 发起 | 条件 | 通过 |
|---|---|---|---|
| Kick（踢出） | 任意真人 | 局内 ≥ 3 min；每人每 5 min 最多发起 1 次；对象不得是管理员 | 投票 45 s；通过条件：赞成票 ≥ 同队在线人数的 50% 且 ≥ 3 票，且赞成 > 反对 × 2【待调参】 |
| Remove Commander（罢免指挥官） | 队内 Officer ≥ 2 人联署 | 在任 ≥ 10 min | 同队 ≥ 40% 赞成（含联署者）|
| Map Vote | 局终自动 | 3 个候选 | 得票最高；平则随机 |
| Mute（静音） | 管理员/发起 | — | 管理员即时执行；玩家发起需同队 ≥ 6 票 |
| Surrender（投降） | 禁用（本版） | — | — |

### 19.4 挂机（AFK）

| 状态 | 判定 | 处理 |
|---|---|---|
| 局内存活 | 120 s 无有效输入（移动、视角、射击、交互、语音、聊天、地图操作） | 90 s 起提示；120 s 起 30 s 倒计时；到时踢出（Squad leader/Commander：150 s + 30 s）|
| DEPLOY/KIA 中 | 300 s 无输入 | 踢出 |
| 载具中不动 | 同局内规则；载具标记为"无人驾驶"后回收计时 | — |
| 脚本检测 | 重复同一输入序列（如固定间隔摇晃） | 视为 AFK 并计入统计异常（§19.5）|

小队长 AFK：自动移交队长（§4.3）；Commander AFK：自动弃权，Commander 席位释放。

### 19.5 服务器端校验与反作弊（玩法侧接口）

> 机制见 ARCHITECTURE.md；此处给玩法层阈值。

| 项 | 阈值 | 处理 |
|---|---|---|
| 位移速度 | > 姿态/速度上限 ×1.15（持续 0.5 s） | 回滚 + 计 1 次违规 |
| 射速 | 超过 `cap` 或 `rpm` ×1.1 | 丢弃多余开火 + 违规 |
| 弹药 | 客户端声称的弹药 ≠ 服务器 | 以服务器为准 |
| 命中回溯 | 延迟补偿 > 250 ms | 使用上限 250 ms |
| 穿墙命中 | 命中前射线被不可穿材质阻挡 | 丢弃命中 |
| 爆头率统计 | 同一玩家连续 50 次命中爆头率 > 60%（排除狙击/近距离）| 标记可疑，管理员审查 |
| 自瞄特征 | 命中前视角角速度突变、跟踪抖动方差异常 | 标记可疑 |
| 违规累计 | 10 min 内 ≥ 8 次 | 踢出；≥ 3 次踢出 → 账号/IP 临时封禁 |

- **诚实声明**：浏览器客户端不可信，无法做内核级反作弊；自瞄/透视只能靠服务器权威、AOI 数据最小化和统计检测缓解，不能根除。

### 19.6 管理员工具与举报

- 管理员（服务器 token 授权）：踢人、封禁（时长 1 h/24 h/7 d/永久）、强制换队、静音、换图、广播、查看聊天日志、查看玩家举报与可疑统计。
- 玩家举报：原因（作弊/辱骂/捣乱/TK）+ 最近 60 s 回放记录（服务器保留 5 min 环形缓冲，仅在被举报时落盘）。
- 所有封禁决定记录审计日志。

### 19.7 对局生命周期

| 阶段 | 规则 |
|---|---|
| 空闲（Idle） | 无真人时服务器空载（bot 不运行）；首位真人加入后开始预热 |
| 预热（Warmup） | 60 s；玩家部署、不可占点；重生计时 ×0.5（§10.6）；若 ≥ 2 名真人或 60 s 到期则开局 |

## 20. Bot 行为需求（玩法角度）

> Bot 运行于服务器；由 `crates/bots` 实现（Recast 导航 + 行为树 + 效用 AI）。本章定义**为了填充对局，bot 必须能做什么**，以及与真人的公平性约束。

### 20.1 层级

| 层 | 职责 |
|---|---|
| Commander bot | 每队 1 个（若无真人 Commander）：资源与能力调度、发布 Command 标记、选择载具 |
| 小队长 bot（Officer/Armor/Recon 队长） | 选择当前目标、给队员下达移动/攻击/防守命令、放置 Outpost、与 Commander 交互 |
| 士兵 bot | 战术行动：移动、战斗、使用兵种能力 |
| 可选 LLM 指挥官 | 总纲规定：每队 1 个、每 **60 s** 决策一次（R4；总纲原为 45 s，已改）、输入为结构化战况 JSON、输出为**受限动作枚举**（动作集合必须是 §13 能力与 §16.3 标记的子集），每局成本上限 0.5 美元（价格未核实，实现前按官方价格重算），超预算回退规则式指挥官 |

### 20.2 填充规则

- 目标：每队总数 50（含 Commander）；真人优先；bot 填补空位（§2.4）。
- 兵种配置：bot 按编制需求自动填充小队，优先保证关键兵种存在：每个步兵小队尽量有 Officer、Medic、Engineer（至少每队 3 个 Engineer）、Support（至少 3）、Anti-Tank（至少 2）；装甲/侦察小队只在有真人认领或 Commander bot 判断需要时才开启；
- bot 昵称带 `[BOT]` 前缀；对局内可见；服务器浏览器显示 bot 数；
- 真人加入某队：该队 bot 立即让出（先从未出生的/等待部署的 bot 开始）；
- bot 难度：Recruit / Regular / Veteran（见 §20.6）。

### 20.3 战术行为需求（逐条可验收）

| 编号 | 行为 | 要求 |
|---|---|---|
| B-01 | 导航 | 在 Recast 网格上寻路，处理楼梯/窗/翻越点（off-mesh link）、避开铁丝网/地雷（已知）、避让载具 |

### 20.4 Commander bot 策略要求

| 编号 | 要求 |
|---|---|
| C-01 | 每 15 s 评估战况：当前活动线、人数优势、资源；选择优先级（占点 > 建造 Garrison > 支援火力 > 载具） |
| C-02 | 资源使用规则：保留 ≥ 100 Manpower 作为 Airhead 预算；Fuel ≥ 120 时才呼叫重型/中型载具；Munitions ≥ 350 且前线存在聚集目标时才用 Bombing；其余同理 |
| C-03 | 能力使用：Supply Drop 在前线 Engineer 补给不足时；Ammo Drop 在前线小队持续战斗 ≥ 120 s；Recon Flight 在进攻前 60 s；Rally 在进攻小队接敌前 5 s；Airhead 在敌方切入后方、或己方重生点被封锁时 |

| C-05 | 载具呼叫：根据队内是否有 Armor Crew 与 bot 数量决定 |
| C-06 | 所有指令频率限制与真人相同（冷却、资源、全局锁） |

### 20.5 性能预算

- 同一对局最多 100 个 bot（实际受真人数影响）；决策 10 Hz（错开），导航查询批处理；单局 bot 每 tick 预算 ≤ 3 ms（目标 ≤ 8 ms 总，服务器 30 Hz 模拟总预算见 ARCHITECTURE.md）。
