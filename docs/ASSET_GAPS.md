## 1. 使用说明

### 1.1 每个 GAP 怎么决定

每个 GAP 有三个选项，你在末尾的 `决定：` 行勾一个（也可以写"推迟到 Mx"）：

1. **继续找**：沿"具体搜索方向"再搜一轮（可交给执行者；搜到候选后回到 `ASSET_SHOPPING_LIST.md` 对应行补全）。
2. **委托外包**：按"估算区间"向外包方询价。外包合同必须写明：原创建模/录制、无第三方游戏资产、授权范围含网页分发、交付源文件；真人配音/重新录音属"重新录音"，**须你本人决定，执行者不得自行推进**（见 `ASSET_SHOPPING_LIST.md` §2.2）。
3. **最接近替代品**：接受史实/风格偏差，用现有素材近似。每项都写明偏差。

### 1.2 GAP 编号规则

- `GAP-Vnn` = 视觉（原调研片段 G1–G16 依次对应 `GAP-V01`–`GAP-V16`；`GAP-V17`–`V19` 是合并时从需求表中补列的缺口）。
- `GAP-Ann` = 音频（原调研片段 A.3 的 13 行依次对应 `GAP-A01`–`GAP-A13`；`GAP-A14`、`A15` 是合并时从需求表中补列的缺口）。
- "对应需求 ID"沿用调研片段原 ID。

### 1.3 与 D-MOD 的关系

多个"替代"选项依赖"对现成素材做减面、重绑定、拼装、重材质"。这些是否算"自制"尚待你最终确认（D-MOD，默认允许：转换/LOD/压缩/重定向/权重传递/材质参数/组合装配；不允许：从零建模/雕刻/重画贴图/AI 生成）。依赖该确认的 GAP 在"建议"里标注。

## 2. 缺口清单

### 2.1 视觉缺口

#### GAP-V01 带内饰且炮塔/炮/履带/车轮可动的坦克

- **对应需求 ID**：V-VEH-US-003（M4 Sherman，M1 的 1 辆坦克）、V-VEH-GE-003（Panzer IV）、V-VEH-GE-004（Panther）、V-VEH-GE-005（Tiger I）；相关 V-ANM-008。
- **缺什么**：外观完整 + 炮塔旋转/炮管俯仰/负重轮悬挂层级可动 + 可用内饰（炮手/车长位）的二战坦克。
- **为什么现有候选不合格**：搜到的坦克多数是外壳模型，少数"rigged"（炮塔/炮管/轮/履带可动），**几乎没有可核实的内饰**；"rigged"通常只是炮塔/履带/轮分层，不是物理驱动用层级，需在管线中重新整理；面数波动大（5k 到 60 万；Sherman 一件 62.3 万多边形需大幅减面）；第一人称坦克炮手视角（含瞄准镜）也缺少现成素材。另一件"含部分内饰"的 Tiger I 被标注为 AI 辅助制作，已排除。
- **选项**
  - ① 继续找：在 Fab/CGTrader 搜 "tank interior" "hatch" "turret basket"；询问现有候选卖家（如 CGTrader Sherman M4 Gameready Rigged、Fab Panzer IV Production models）是否有内饰版。
  - ② 委托外包：US$1,500–6,000/辆（含内饰与绑定）【估算】。
  - ③ 最接近替代：买外壳 + 做"简化内饰盒（炮手/车长位置）"，只在第一人称炮手位置显示。**偏差**：无真实内饰细节，乘员舱为简化盒体；"重新整理层级、做简化内饰盒"需 D-MOD 确认。
- **建议**：M1 采用 ③（外壳 + 简化内饰盒），因为 M1 只要 1 辆可玩坦克；待 M1 试玩后，M3 再决定是否外包 1–2 辆带内饰坦克。若外包，先询价。
- **影响里程碑**：M1（1 辆坦克）、M3（全载具）。

## 3. 灰盒占位约定

目的：**素材未到位时，开发不被阻塞**。占位让玩法、物理、网络、AI 能在正确尺寸与碰撞下先跑起来；素材到位后用同一需求 ID 替换，不改代码。

### 3.1 通则

1. **每个占位绑定一个需求 ID**（`V-…` 或音频 ID，如 `A-WPN-001`）。素材管线按需求 ID 查找真素材；找不到则生成/使用占位。
2. 占位是**程序生成的基本几何体**（盒、圆柱、胶囊、球），不是素材：不进 `assets/incoming/`，不登记 `LICENSES.md`。（若你认为程序化灰盒也算"自制"，请告知，执行者改用引擎内置的调试图形。）
3. 占位必须有**正确尺寸与碰撞体**：数值取自 `/data` 下的数据文件（武器/载具/角色尺寸字段，单位 m），不得写死在渲染代码里；若数据文件暂缺尺寸，使用真实史实尺寸并在数据文件中补字段，注明来源。
4. 占位必须**可辨识、可自动检测**：材质命名 `PH_{需求ID}`，场景节点命名 `PH_{需求ID}__{实例名}`；调试渲染叠加显示需求 ID 标签（仅开发/内部构建）。
5. 占位**保留与真素材相同的挂点（socket）约定**，如武器的 `socket_muzzle`、`socket_ejection`，载具的炮塔/炮管/轮位，角色的手部握持点，确保真素材换上时玩法逻辑不变（挂点命名以 `ARCHITECTURE.md`/数据约定为准，执行者不得自行发明与之冲突的命名）。
6. 占位一律着阵营色以便读图：美军橄榄绿、德军灰（仅为调试配色，非最终美术）。

### 3.2 视觉占位对照表

|---|---|---|---|
| 地表材质 | 优先使用免费 CC0 真材质（Poly Haven/ambientCG）；未到位用棋盘格 | 地形系统 | 地表是唯一"免费即达标"的品类，不应长期占位 |
| 武器（第一/第三人称） | 长方体 + 圆柱组合（枪身/枪管/弹匣），按真实长度 | 无（持枪由角色处理）；投掷物用球 | 保留 muzzle/ejection/magazine 挂点；第一人称与第三人称各一个占位（D-FP 精度不同，占位同形） |

### 3.3 音频占位

1. **静音占位**：缺失的音效返回一个短静音 `AudioBuffer`（例如 0.1 s），保证播放链路、距离分层、混音总线和 AudioWorklet 全部正常运行，不报错、不崩溃。
2. **日志**：每个缺失的需求 ID **每个会话只打一条** `[asset-missing] audio {需求ID} requested by {事件名}`（开发/内部构建；生产构建只计数上报，不打印）。
3. **默认不放"提示音"**：占位保持静音，避免占位音误当最终音（如需调试，可在开发构建里开关"缺失音效 beep"，该开关默认关闭）。
4. **分层完整性**：距离三层（近/中/远）缺哪层，都按"该层静音"处理，不用其它层顶替，避免掩盖缺口。
5. 音乐占位：静音 + 日志；不用任何版权不明的音乐"凑数"。

### 3.4 检测与验收

1. 资源管线（`/tools/asset-pipeline`）在每次构建输出**缺失素材报告**：列出每个需求 ID 的状态 `real / placeholder / missing`，并按里程碑汇总。
2. 清单进 git：`assets/processed` 的 manifest 带 `placeholder: true/false` 字段；占位项允许存在于主分支，**真素材必须先在 `LICENSES.md` 状态为 OK 才能进入 manifest 的 `real`**。
3. **里程碑验收门槛**：某里程碑验收时，该里程碑范围内（`ASSET_SHOPPING_LIST.md` §4.x）仍为占位的需求 ID 必须在本文件里有对应 GAP 的"决定"，或你明确写"推迟到 Mx"。
4. 执行者遇到缺失素材时**不得自行去非正规渠道找素材、不得自制、不得 AI 生成**；只能使用占位并在任务回报里列出缺失的需求 ID。

### 3.5 替换流程

素材到位 → 放入 `assets/incoming/{需求ID}/…` → 在 `LICENSES.md` 登记并状态 OK → 管线处理（`.fpak` 打包）→ 同一需求 ID 覆盖占位 → manifest `placeholder` 置 false → 视觉回归/听感检查 → 在 `ASSET_SHOPPING_LIST.md` 勾选"已购"。
