## 背景
UI_SPEC §6 定义：设计基准 1920×1080；`--pl-ui-scale = clamp(0.667, min(vw/1920, vh/1080), 2.0) × userScale`（用户 75–200%）；最小窗口 1280×720，字号下限（计算后 < 11 px，中文 < 12 px 则夹紧并允许紧凑变体）；`devicePixelRatio` Canvas 上限 2×。
断点（§6.2）：Compact（高 < 800 或宽 < 1500）、Standard（1500 ≤ 宽 < 2560）、Large（2560 ≤ 宽 < 3440，菜单最大容器 1600 px，HUD 缩放上限 1.5×）、Ultrawide（宽高比 ≥ 2.1:1）。
安全区（§6.3）：HUD 安全框左右各 `max(48 px, 2.5% 宽)`、上下各 `max(32 px, 3% 高)`（× `ui-scale`）；设置可调 0–10%；模态与面板完全落在安全框内。
超宽（§6.4）：HUD 锚定 16:9 中央区域（设置项"HUD 宽度"默认"16:9 居中"，可选全宽）；战术地图/记分板地图保持方形居中，两侧放图层栏；部署界面最大容器 2000 px 居中；宽高比 < 1.3 显示"请使用更宽的窗口"并禁用部署界面。
**测试矩阵（§6.5）**：1280×720、1366×768、1920×1080、2560×1440、3440×1440、3840×2160；Playwright 视觉回归覆盖每屏 × 以上分辨率 × 两种语言（中文文本最长、英文最宽）。16:10 与 32:9 为**可选扩展**（§6.5 原表未含，已裁定降为可选，不计入验收）。

## 具体内容
### 要创建/修改的文件
- `tests/e2e/ui_matrix.spec.ts` —— 视口矩阵 × 屏幕 × 语言 的截图与断言。
- `tests/e2e/ui_matrix.config.ts` —— 矩阵：6 个 §6.5 分辨率 + 1920×1200（16:10）+ 5120×1440（32:9）两项**可选**扩展（已裁定降为可选，不计入验收）。
- `client/src/ui/layout/{SafeArea,UiScale,HudAnchor}.ts(x)` —— 缺陷修复（若已存在则只修复）。
- `client/tools/layout/overflow-check.ts` —— 检测 HUD/面板越出安全框与文本溢出。
- `reports/ui/m4-matrix.json`。
### 要实现的行为
1. 对 §4 全屏幕（至少：启动、主菜单、浏览器、阵营、部署、HUD、战术地图、记分板、设置、结算、暂停）在矩阵每个分辨率两种语言各截图并跑 `overflow-check`。
2. 修复发现：越出安全框、文本截断、字号下限未生效、超宽 HUD 偏移、`dpr` Canvas 超限、窄窗口提示缺失。
3. HUD 在 21:9 / 32:9 下默认锚定 16:9 中央区域，切到"全宽"后元素位置合理；战术地图保持方形居中（不拉伸）。
4. 1280×720 紧凑变体（击杀播报 2 条、小队成员 ≤ 6 行）与 1366×768 Compact 记分板隐藏次要列。
5. 4K（3840×2160）下 Canvas `dpr` 上限 2×，地图单次重绘 ≤ 2 ms（200 单位 + 100 标记，UI_SPEC §8.1）。
### 接口与数据
- `overflow-check` 输出：`{screen, viewport, lang, issues:[{type:'out_of_safe_area'|'text_overflow'|'font_below_min', selector, rect}]}`。

## 不做什么

- 不重做 UI 视觉设计；只修复布局缺陷。
- 不做移动端/手柄（A4）。

## 验收标准
1. **UI §6.5 矩阵全部通过**：6 个分辨率 × 全屏幕 × 2 语言，`overflow-check` issues = 0（`reports/ui/m4-matrix.json`）。
2. **HUD 不越出安全框**：安全框 = 左右 `max(48 px, 2.5% 宽)`、上下 `max(32 px, 3% 高)`（×ui-scale）；HUD 元素边界矩形 100% 在框内（断言）。
3. 字号下限：1280×720 下所有文本计算字号 ≥ 11 px（中文 ≥ 12 px）；失败数 = 0。
4. 超宽：3440×1440 下 HUD 左右边缘与 16:9 中央区域对齐（误差 ≤ 2 px）；战术地图外接矩形为正方形（宽高差 ≤ 1 px）。
5. 宽高比 < 1.3（如 1000×900）：部署界面被禁用并显示提示文案（e2e）。
6. 扩展矩阵（1920×1200、5120×1440）：issues = 0 或登记 PLAN_ISSUES 并写出豁免原因。
7. 4K：地图重绘 ≤ 2 ms（`performance.now()` 100 次中位数），`dpr` 上限 2× 断言。

## 测试要求
- 单元测试：`vitest`：`ui-scale` 公式与夹紧；安全区计算；字号下限函数。
- 集成/无头测试：Playwright 矩阵（`pnpm -C client test:matrix`），视觉基线按 `分辨率/语言/屏幕` 存储。
- 性能基准：4K 下 UI CPU ≤ 1.5 ms 均值；地图重绘耗时。
- 回归：基线并入 M4-040（UI 部分）。

## 性能预算
- UI_SPEC §8.1：UI 总 CPU ≤ 1.5 ms 均值/≤ 3 ms P95；地图单次重绘 ≤ 2 ms；DOM 节点上限不变。
